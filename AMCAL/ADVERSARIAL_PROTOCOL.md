# Approved AMCAL policy on tabular adversarial domains

`amcal_adversarial_protocol.py` reuses the approved IAT training and online
engines: the original CNN/feature-token Context architecture, two-stage source
training, three Context clones, seven coupled actions, shared correctness
scorer, DDQN, and **class-balanced macro reward reference**. It does not enable
decoupled queries, the budget-v2 policy, or an external quality controller.

Each attack has an independent CNN refinement, Context, selector and result
directory. Source row IDs and the train-only scaler come from an existing
protocol-v3 **clean-only CNN** run. This avoids training the same clean CNN four
times. The clean Context/RL phase is trained, then the CNN is refined on clean
and attack level 2, followed by 20 epochs of Context pretraining against that
CNN and source RL training. The final balanced seven-action selector is trained
on those same two domains. Default online Context LR is 0.0005, cap 20%, gamma
0.95 and test epsilon 0.05. Legacy source-episode LR stays 0.0001, as in the IAT
source pipeline; the final bank uses 0.0005.

## Levels and attack construction

Level 0 means the original clean CSV. Levels 1..5 are ordered strengths:

| Attack | Level 1 | **Level 2: training** | Level 3 | Level 4 | Level 5 | Radius norm |
|---|---:|---:|---:|---:|---:|---|
| FGSM | 0.01 | **0.05** | 0.1 | 0.2 | 0.5 | L-infinity |
| PGD | 0.01 | **0.05** | 0.1 | 0.2 | 0.5 | L-infinity |
| projected CW-L2 | 0.1 | **0.5** | 1 | 2 | 5 | L2 |
| budget-capped DeepFool-L2 | 0.1 | **0.5** | 1 | 2 | 5 | L2 |

The numeric radii are in TRAIN StandardScaler feature units; they do not have
identical meanings across the two norms. No image-style [0,1] clipping or
packet-realizability constraints are applied. CW optimizes squared L2 plus an
untargeted logit-margin hinge, with per-example binary search of the tradeoff
constant and explicit L2 projection. Defaults: 100 Adam iterations at LR 0.01,
3 search rounds, confidence 0. DeepFool uses all classes, nearest linearized
decision boundary, overshoot 0.02, at most 25 steps, then L2 radius capping.
PGD uses a random start and 20 projected steps of size 2*radius/20. Defaults are
finite computational attack settings, not guarantees of finding worst cases.
These are newly generated, explicitly specified feature-space domains; they
are not claimed to reproduce the unknown settings of the legacy CSV attacks.

The attack source is the fixed clean CNN, whose parameters never change during
generation. After the base CNN is refined, these are **fixed-surrogate transfer
attacks**, not adaptive white-box attacks against the final seven-action bank.
Attack manifests include clean/attacked surrogate accuracy, success conditional
on initial correctness, radius checks, source/model hashes and original row maps.

References for the underlying algorithms:

- FGSM: https://arxiv.org/abs/1412.6572
- PGD: https://arxiv.org/abs/1706.06083
- CW: https://arxiv.org/abs/1608.04644
- DeepFool: https://arxiv.org/abs/1511.04599

## Source separation and evaluation

Only TRAIN and validation source IDs are perturbed during training; TEST attack
rows are generated by the separate evaluate command. Legacy 1200-row SDNCampus
attacks with unconfirmed mappings are not imported. All fresh attack rows carry
explicit original source IDs. Feature-identical clean source groups remain
apart in the saved partitions. No raw source/legacy attack file is overwritten.

Evaluation includes all six domains by default. Clean and level 2 are marked
**Seen**: the intensity was available during training, while source rows are
disjoint heldout TEST rows. Levels 1,3,4,5 are marked **Unseen**. Aggregate unseen
means exclude clean and level 2. Both learned and random policies receive the
same 20% per-domain cap; a policy may spend less. Prediction precedes paid
feedback. Models, optimizer states, histories and replay reset per domain/mode.
Oracle and retention observers do not provide labels/rewards to learners.

## SDNCampus commands (PowerShell)

No new library is required beyond the existing AMCAL environment. First run the
small tensor/provenance checks on the local machine that has PyTorch:

```powershell
git pull --ff-only origin experiment/amcal-protocol
python -m unittest discover -s AMCAL/tests -p test_adversarial_domains.py -v
$data = "AMCAL/SDNCampus_TEST/Dataset"
$clean = "AMCAL/SDNCampus_TEST/protocol_runs/shared_two_action_lr0p0005_seed42"
$run = "AMCAL/SDNCampus_TEST/protocol_runs/structured_bank3_balanced_level2_seed42"
```

Train all four attacks sequentially; it does not test heldout rows:

```powershell
python AMCAL/amcal_adversarial_protocol.py train --attack all --data-dir $data --source-file SDNCampus_original.csv --clean-run $clean --output $run --context-lr 0.0005 --budget-fraction 0.2 --selection-cost 0.0001 --gamma 0.95 --seed 42 --device cuda
```

Test separately, including clean/level 2 heldout rows and the four unseen
intensities, with epsilon 0.05:

```powershell
python AMCAL/amcal_adversarial_protocol.py evaluate --attack all --data-dir $data --source-file SDNCampus_original.csv --output $run --levels 0 1 2 3 4 5 --context-lr 0.0005 --budget-fraction 0.2 --selection-cost 0.0001 --gamma 0.95 --eval-epsilon 0.05 --seed 42 --device cuda
```

For one attack first, replace `--attack all --output $run` with
`--attack FGSM --output "$run/FGSM"`. Use PGD, CW or DeepFool similarly, including
when running in independent tabs. Avoid concurrent runs when comparing runtime.
Default epoch limits are clean source RL 12, CNN refinement 30, source RL 30,
and structured RL 12. The original Context pretraining remains 20 epochs per
stage. Epoch controls are `--stage1-epochs`, `--cnn-epochs`, `--source-epochs`
and `--bank-epochs`; shortening them changes the training budget and should be
reported. The successful IAT architecture/reward is reused without new tuning.

For stream-seed repeats, evaluate the same trained run with `--seed 48`, etc.
Attack datasets stay fixed at their recorded generation seed. These are stream
seed repeats, not independent CNN/RL training repeats.

## Files

For `--attack all`, each attack has these directories under `$run/<Attack>`:

- `Surrogate/Models`: original clean attack-source CNN and preprocessing.
- `TrainingDomains`: clean CSV and mapped level-2 TRAIN/validation attacks.
- `Source/Models`: the two-stage CNN/Context source checkpoints.
- `Bank/Models`: the approved balanced seven-action policy and initial models.
- `EvaluationDomains`: cached mapped TEST attacks; reused across stream seeds.
- `Bank/Results`: per-level traces, metrics, oracle, budget, timing and retention.
- `Results/adversarial_summary_seed42.csv`: named attack/intensity summary.
- `adversarial_training.json`: source hashes, settings, level mapping and status.

The top-level `$run/Results/all_attacks_seed42.csv` combines all modes/domains.
Console summaries are readable tables, not JSON. Internal shared-engine cache
filenames use its existing domain layout; no Burst data are used in this run.
Training requires a fresh output directory and never overwrites prior models.

## Existing baselines on the identical mapped domains

After the four AMCAL training runs complete, use
`amcal_adversarial_baselines.py train --amcal-run <AMCAL root> --output <fresh baseline root> --attack all`.
It trains CNN, RAL, AF, DFE, ARF, CALMID and MicFoal separately per attack.
CNN reuses the final AMCAL Frozen checkpoint; the other methods retain their
existing implementations/defaults and fit exactly the clean/level-2 TRAIN rows.
Validation uses the corresponding validation IDs. No test attack is generated
or scored by the baseline training command.

Use the same wrapper with `evaluate`, the same roots, `--data-dir <original data>`
and `--source-file <original.csv> --levels 0 1 2 3 4 5` afterwards. Evaluation
reuses/generates the AMCAL TEST-only mapped domains from its saved clean surrogate;
training attack hashes are checked in the separate TrainingDomains directory.
Seen intensities (0/2) are explicitly allowed only on disjoint TEST IDs.
Models reset per level. The baseline's native query rule is retained under the
common 20% cap, and its budget, runtime and retention tables are unchanged.
The consolidated accuracy/budget summary is `Results/all_baselines_seed42.csv`.
Existing per-attack Results also retain timing, same-level retention and traces.
Attacks are fixed source-CNN transfer attacks, not model-specific direct attacks.
Baseline source CNN and attack generation are reused; there is no redundant CNN
training, data download, or modification to the approved AMCAL RL method.

## Supplied Dense-generated attacks (no new attack generation)

`amcal_supplied_attack_protocol.py` uses the existing original CSV and the five
CSV files in each FGSM/PGD/CW/DeepFool folder, byte-for-byte. The dataset owner
specifies that these attacks targeted a generic Dense surrogate. Use a fresh
output root, separate from the generated-CNN-attack experiments above.

Commands: `train`, `evaluate`, `train-baselines`, `evaluate-baselines`; default
`--attack all` runs all four sequentially. Source CNN/Context use the same
clean-first, multishift second-stage engine. The final structured bank retains
the approved coupled seven actions and class-balanced reward reference, policy
queries, learned update destinations, LR .0005, gamma .95 and cost .0001.
No decoupled query, external controller or budget-v2 policy is enabled.

Alignment assumption: supplied attack rows are assigned the historical
stratified 80/20 original-source pool order (random_state=42). Previous label
sequence matching supports this candidate, but does not establish provenance.
This assumption, and the owner's Dense-surrogate statement, are recorded in
`supplied_attack_training.json`. They must not be described as independently
verified generation provenance. Existing data are never overwritten.

The 1200-row SDNCampus attack pool is split 720 TRAIN / 240 validation / 240
TEST, with corresponding source IDs kept together across intensities. The
remaining clean source rows enter only clean TRAIN/validation. Exact-feature
cross-partition overlap is removed by the existing official loader. Consequently
TEST may contain slightly fewer than 240 rows after that filter. This experiment
has a different split/test size from the earlier generated-attack experiment;
its scores must not be mixed into that experiment's results.

Only clean and ordinal attack level 2 enter training (FGSM/PGD .05;
CW/DeepFool .5). Other intensities are scored only on TEST source IDs.
Clean and level 2 can also be scored on their TEST rows as seen intensities.
All baselines reuse these exact partitions and domains, and CNN reuses the final
Frozen CNN. Source and attack domains may have different partition sizes; the
optional partial-domain artifact flag enables this without weakening the default
full-coverage checks for existing Burst experiments.

### Parallel independent baseline execution

To start baselines immediately while AMCAL is training, use a **different fresh
output root** and `train-baselines --independent-baselines`. This creates the same
supplied domains and deterministic source partitions independently, fits a CNN
with clean-first and clean+level-2 refinement stages (same architecture, epochs,
patience and loss), and trains all seven baselines. It never waits for or loads
AMCAL Context/selector checkpoints. CNN weights are independently trained and
are not guaranteed to equal AMCAL's Frozen CNN because the intervening AMCAL
Context/RL stage consumes random numbers. The training manifest explicitly
records independent CNN initialization. No architectural/reward change is made
to AMCAL. `evaluate-baselines` detects that source from its saved manifest.
For final runtime comparisons run methods sequentially without concurrent GPU
jobs; parallel execution is useful for initial accuracy experiments.

### Full-file testing at other intensities (updated supplied-data protocol)

The supplied-data wrapper now passes `--full-unseen-levels` automatically for
both AMCAL and baseline evaluation. Levels 1, 3, 4, 5 are scored on **all rows of
each supplied CSV**, not just the source TEST-ID intersection. Clean and training
level 2 still use only their saved TEST source IDs. Training, validation and model
weights are unchanged; existing models can be evaluated again without retraining.
For SDNCampus, unseen-level streams therefore contain 1200 rows and have a 240
label cap, whereas the previous default scored about 239 rows with a 47 label cap.

This evaluates generalization to unseen **intensities**, with source sample IDs
allowed to recur from training at level 2. It must not be called source-disjoint
heldout testing. It supersedes the earlier TEST-only statement for unseen levels
in the supplied-data section. The new protocol is included in metric execution
configurations and result filename hashes so old metrics/traces remain available.
Generic bank/baseline commands retain their previous heldout behavior unless the
explicit flag is supplied. Training rejects the full-file flag.
