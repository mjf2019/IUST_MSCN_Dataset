# Stage 1: Context-only class-balanced rehearsal

Default --context-memory off preserves the baseline. Enable --context-memory per-class --memory-per-class 32 --memory-batch-size 16 --memory-weight 1.

This is a separate CPU memory, not DQN replay. Each occupied class has a FIFO deque with a fixed cap. Rehearsal samples round-robin over a shuffled class list, without replacement within a minibatch, using a private seeded RNG. Features are detached cloned snapshots. For each online queried row, the Context loss is existing context_objective(new sample) + beta * unweighted CE on the sampled memory rows. Balanced memory CE deliberately avoids class-frequency weighting. Gradients pass through the frozen classifier to Context. The current queried row is inserted only AFTER its optimizer update, preventing double-counting it in its own replay minibatch.

Online memory starts empty once per perturbation level and persists across classes. It admits only examples actually queried under the existing total/per-class budget. Skipped/rejected rows and heldout rows never enter. Reusing a previously purchased label incurs no new query budget. Trace fields distinguish memory_loss, replay_samples, memory_size_before/after; diagnostics report memory size per class, total admitted samples and replayed samples. Runtime guards compare admitted sample count to actual queries and reject heldout intersection. No replay-only update occurs after a class/global cap: existing update eligibility remains intact.

Both learned and random online runners share exactly the same memory/loss helper. In offline training, memory begins after CE-only Context warmup and is used during the joint RL/Context phase; only actually selected original rows are admitted (singleton BN duplication is excluded). Offline memory is transient and is not loaded into online evaluation. Training memory settings are recorded in checkpoints; online memory can be toggled independently to compare the SAME initial checkpoint. Existing checkpoints remain usable without retraining.

Results append _context_memory32_batch16_weight1 (values reflect configuration), leaving baseline folders intact. Architecture, RL reward/state, query policies, quotas, holdout, learning rates and pretrained CNN are unchanged. This does not promise no forgetting: test final heldout per-class recall and macro F1 against the matched memory-off run. No rollback, distillation or meta-training is introduced in stage 1.

Validation: source compilation; actual CLI parser and invalid option checks; class caps/FIFO; balanced sampling/no repeated draws; independent RNG/reproducibility; exact loss identity when disabled/empty/beta=0; static query-only insertion after optimizer step. test_context_memory.py includes a real CPU PyTorch test for detached snapshots, additive loss and Context gradients through a frozen classifier. Locally four standard-library tests passed; one PyTorch test was skipped because PyTorch is unavailable. No dataset training/evaluation was run locally.
